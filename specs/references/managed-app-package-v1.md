# Managed native application package v1

This reference freezes the local `.i2prapp` artifact format implemented by
`i2pr-app-package`. It records package integrity and publisher-key identity;
trust, grants, selection, and launch authority belong to the separate Plan 374
policy layer.

## Container and limits

The artifact is one ZIP file. Version 1 accepts Stored regular-file entries
only. Directories, compression, encryption, duplicate names, unknown top-level
namespaces, absolute paths, NUL, backslash, dot components, symlinks, devices,
FIFOs, and sockets are rejected. No generic extraction API is used. Archive
mode, timestamps, ownership, ACLs, and extended attributes are never applied.

| Value | Ceiling |
| --- | ---: |
| Archive bytes | 512 MiB |
| Payload files | 4,096 |
| One payload | 256 MiB |
| Total payload | 512 MiB |
| Inventory JSON | 1 MiB |
| Manifest JSON | existing 64 KiB contract ceiling |
| Package path | existing 512-byte grammar |

The required entries are exactly `manifest.json`, `inventory.json`,
`publisher.ed25519`, and `signature.ed25519`. Payload files live only under
`payload/<PackagePath>`. Paths use the contract crate's ASCII grammar, reject
Windows-reserved components on every host, and may not collide under ASCII
case-folding.

## Inventory and publisher identity

`inventory.json` is a strict JSON array of records with exactly `path`, `size`,
`sha256`, and `executable`. It is sorted by path bytes. Digests are 64 lowercase
hexadecimal characters. Each payload entry and inventory record has a one-to-one
match, including exact size and SHA-256. Manifest entrypoints must be inventoried
as executable; an optional UI resource must be inventoried.

`publisher.ed25519` is exactly 32 raw bytes. The package publisher id is the
lowercase hexadecimal SHA-256 digest of those bytes and must equal the signed
manifest `publisher_id`.

## Signature transcript

`signature.ed25519` is exactly 64 raw bytes and strictly verifies over:

```text
"I2PR-APP-PACKAGE-V1\0"
|| u32be(manifest_length) || exact manifest.json bytes
|| u32be(inventory_length) || exact inventory.json bytes
|| publisher.ed25519
```

The implementation verifies the same exact JSON bytes it decodes. Payload
hashes are transitively bound by the signed inventory.

The executable golden is `signature_transcript_has_a_stable_ed25519_golden`
in `i2pr-app-package`: manifest bytes
`{"schema_version":1,"app_id":"golden.app"}`, inventory bytes `[]`, and the
fixed public test signing key derived from the source's `[7; 32]` fixture seed
produce transcript SHA-256
`835ba3477b01737f0708db55ed15d0471aae4219a84a968f311cc2c815b6b687` and
signature
`6c94150caa8662be04a5fceefb6a1467c69e588cdf0f9847e0bee30c081c2578490d3e3115dc570ee4676e77a3b3cfe5887b4206342cec3fe1a887c48af37409`.
The seed is test-only and has no relationship to a publisher identity.

## Local installation

The store copies a source artifact once to a new private staging file while
computing the artifact digest, syncs it, and then verifies/materializes only that
copy. Payload files are created with create-new semantics under a fresh private
staging directory and hashed while written. A receipt is generated by the
store. The complete directory is synced where supported and atomically renamed
to:

```text
packages/<publisher-key-id>/<app-id>/<version>/<artifact-digest>/
```

An identical artifact reinstall is idempotent. A different artifact for the
same publisher/app/version is a conflict. Staging cleanup only removes direct
children of `.staging` and never follows links. Installed files are reverified
before later authority construction.

## Security meaning

A valid signature only identifies a key that signed these exact metadata bytes.
It does not assert that the operator trusts that key, that requested
capabilities are granted, or that the package is selected or runnable. Package
verification and installation execute no code, scripts, or hooks and access no
network.
