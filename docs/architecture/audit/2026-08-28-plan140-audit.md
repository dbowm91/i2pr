# Plan 140 architecture audit

Date: 2026-08-28

## Result

Plan 140 remains blocked. The local SAM parser, session registry, forwarding
policy, naming policy, and cleanup tests are present and bounded. The daemon
does not yet connect the accepted SAM STREAM socket to a live per-stream raw
bridge backed by destination delivery, so the existing capture seam cannot
serve as independent-client interoperability evidence.

## Source/doc drift corrected

- `SamPrivateDestination` was documented as non-cloneable but derived
  `Clone`; the implementation now has one zeroizing owner and consumes its
  bytes without making a second copy.
- Plan 135 and the top-level status references now identify Plan 140 as an
  attempted, blocked closure rather than an unstarted next plan.
- The SAM support record now separates Plan 139's local hardening from Plan
  140's blocked external-client acceptance.

## Remaining source-of-truth findings

1. `crates/i2pr-daemon/src/sam.rs` still performs STREAM follow-up work inline
   and returns to command processing after status; it has no permanent raw
   handoff.
2. `crates/i2pr-daemon/src/sam/streams.rs` retains captured adapter output as
   a test seam. Normal `SESSION CREATE` does not install a live destination
   bridge with established tunnel material.
3. The repository's strict RFC 4648 SAM Base64 choice must be reconciled with
   the I2P Base64 spelling used by the selected independent client before
   private-destination interoperability can be claimed.
