# Architecture Documentation Audit — 2026-08-27

This document records the findings of a parallel-subagent audit of every
existing file in `docs/architecture/` against the current source tree
on `main` (commit under audit). 16 subagents were dispatched in
parallel, one per doc; each compared doc text to source files and
returned a structured report. The patches applied in the same commit
are cross-referenced below.

The goal was **audit and fill gaps** — apply targeted corrections to
the most-stale claims and create the one missing deep-dive
(`i2pr-netdb-persist.md`), without rewriting the deep-dives whose
content is structurally correct but stale in detail.

## Outstanding gaps (not patched in this commit)

These were surfaced by the audit but require substantial rewrites or
cross-crate surgery and are recorded here as follow-up work.

1. **`i2pr-client.md` is structurally accurate but stale in detail.**
   - `streaming.rs` is a flat file in the doc; source is `streaming/`
     with 13 sub-files (`mod.rs`, `manager.rs`, `connection.rs`,
     `recv_window.rs`, `send_window.rs`, `clock.rs`, `config.rs`,
     `congestion.rs`, `errors.rs`, `events.rs`, `retransmit.rs`,
     `transport.rs`, `testing.rs`).
   - The doc describes `send_data`/`send_close`/`send_reset` as public
     methods; they live inside `process_inbound_packet` and
     `accept_inbound_syn`. The connection-level API is `enqueue_send`.
   - Missing: `Clock`/`SystemClock`/`ManualClock`,
     `StreamingTransport`, `RemoteDestination`/`RemoteDestinationKey`,
     `MAX_ROUTER_SIDE_LS2_BYTES_PER_REMOTE`, `LeaseSetSummary`,
     `DestinationShutdown`, `DestinationProgress`,
     `DestinationRouting::forget_remote`, and `plan132_trajectory.rs`.

2. **`i2pr-runtime.md` is structurally accurate but missing two
   major modules.** The doc does not describe
   `ntcp2_handshake_observer.rs` or `ntcp2_data_oracle.rs`, both of
   which are re-exported from `lib.rs:44-59`. 11 runtime re-exports
   are missing from the public-surface section. The
   `i2pr-transport-ntcp2` runtime dep is missing from the dependency
   table.

3. **`i2pr-transport-ntcp2.md` is structurally accurate but two
   state counts are wrong.** `InitiatorPhase` has 9 variants
   (missing `AwaitCreatedPadding`); `ResponderPhase` has 7 variants
   (missing `AwaitRequestPadding`). Several public methods
   (`ResponderState::phase_label()`, `into_directional_states`) are
   absent.

4. **`i2pr-testkit.md` is essentially accurate.** Two minor items:
   `src/rng.rs` is 198 lines (doc says 182); `SchedulerError` is
   referenced as public but is not in the `pub use` re-exports.

5. **`interop-apparatus.md` is substantially stale.** Plan 099/100
   trimmed the harness; ~30 files the doc still describes as active
   no longer exist. Several plan status tokens cite closure records
   that do not exist (`plans/093-status.md`, `plans/094-status.md`,
   `plans/100-status.md`, `plans/101-status.md`). The full Plans
   115–134 surface (Emissary, destination lifecycle, streaming,
   Milestone 6) is absent. **Recommend a full rewrite when the next
   interop-surface plan lands.**

6. **`i2pr-daemon.md` line refs are drifting.** Doc references
   `main.rs:47-54` for `_command_name`; source is `main.rs:61`. Same
   pattern across other crates.

## Methodology

For each doc:

1. Read the doc end-to-end.
2. Read every source file in the target crate (parallel).
3. Read `Cargo.toml`.
4. Compare doc claims to source reality, line by line.
5. Return a structured report: STALE / MISSING / INCORRECT BOUNDS /
   WRONG LINKS / GOOD, each citing doc-line vs source-file-line.
6. No rewrites were proposed; only findings.

Subagent outputs were aggregated and the highest-impact fixes
(typically wrong numeric constants, wrong crate/module counts, wrong
dependency names, missing crate-level deep-dives, and missing
boundary-script enumeration) were applied in this commit. Detailed
content rewrites for `i2pr-client.md`, `i2pr-runtime.md`,
`i2pr-transport-ntcp2.md`, and `interop-apparatus.md` are out of scope
and tracked above.
