## 1. Why this corrective pass exists

Plan 115 correctly added the canonical production bridge from
`ShortBuildAction::Deliver` to I2NP type 25, but it closed as Branch E after
finding that the cheapest i2pd native consumer still required substantial
router-runtime initialization.

That closure was premature. Plan 115 explicitly allowed switching once from
`i2pd` to Emissary when Emissary exposed a materially smaller native consumer.
A source audit of upstream Emissary shows that this smaller consumer already
exists and is already exercised without a daemon, network socket, namespace,
container, or VM.

Pinned reference for this pass:

```text
reference_repository = https://github.com/eepnet/emissary.git
reference_revision   = 9b43484a21d5a1291c4881cdae62a36c527f8c0f
reference_package    = emissary-core 0.4.0
reference_kind       = emissary
```

At that revision:

- `emissary-core/src/i2np/tunnel/build/short.rs` owns the native 154-byte
  request parser and short-build reply builder.
- `emissary-core/src/tunnel/transit/mod.rs` exposes
  `TransitTunnelManager::handle_short_tunnel_build()`.
- That handler performs target-record lookup, Noise-N request decryption,
  native request parsing, policy acceptance/rejection, tunnel-key creation,
  reply-record transformation, and forwarding/OBEP reply construction.
- `emissary-core/src/tunnel/tests/mod.rs` already provides
  `TestTransitTunnelManager`, including access to the generated router hash and
  X25519 static public key, and forwards directly to
  `handle_short_tunnel_build()`.
- Emissary's own unit tests construct this manager under `MockRuntime` and call
  the native short-build handler for participant, inbound-gateway, and
  outbound-endpoint cases.

The official I2P specifications remain the wire authority. Current specification
index entries mark ECIES-X25519 Tunnel Creation accurate for I2P 0.9.66 and
I2NP accurate for 0.9.66. The short-build format is:

```text
ShortTunnelBuild / I2NP type 25
body = count:u8 || count * 218-byte encrypted records
count = 1..8

short encrypted request record =
    target_hash_prefix[16]
 || ephemeral_x25519_public[32]
 || encrypted_request_plaintext[154]
 || poly1305_tag[16]
```

For an outbound endpoint, the native peer transforms the build into the
outbound tunnel-build reply path and sends it toward the terminal next
router/tunnel specified in the request.

Primary references:

- <https://geti2p.net/spec/tunnel-creation-ecies>
- <https://geti2p.net/spec/i2np>
- <https://github.com/eepnet/emissary/blob/9b43484a21d5a1291c4881cdae62a36c527f8c0f/emissary-core/src/i2np/tunnel/build/short.rs>
- <https://github.com/eepnet/emissary/blob/9b43484a21d5a1291c4881cdae62a36c527f8c0f/emissary-core/src/tunnel/transit/mod.rs>

## 2. Correct development decision

The current environment must not keep Milestone 5 router construction blocked
behind live transport qualification.

This pass therefore changes the gate semantics to:

```text
Q0 native independent consumption       = required bounded attempt now
Q1 authenticated transport delivery     = deferred
Q2 returned live reply -> Established    = deferred
Plan 116 local tunnel data plane         = blocked only by a demonstrated
                                           short-build protocol defect
```

A Q0 pass immediately unblocks Plan 116.

If the bounded Emissary attempt is itself blocked by a reference build/tooling
condition after the correction budget in this plan is exhausted, that is an
**evidence limitation, not a protocol failure**. Record it and proceed to Plan
116 local data-plane work with external short-build evidence explicitly
`deferred`.

Only a reproducible rejection **after Emissary reaches its native short-build
processor** is allowed to block Plan 116, because that is affirmative evidence
of a tunnel-build protocol disagreement.

This rule is the main anti-loop correction.

## 4. Why a one-hop outbound OBEP case is the correct minimum

Use one real outbound hop whose role is `OutboundEndpoint`.

This is intentionally smaller than a three-hop path. One OBEP is sufficient to
exercise the native cryptographic and semantic boundary that Q0 is intended to
validate:

1. Emissary identifies its target record from the 16-byte hash prefix.
2. Emissary extracts the creator ephemeral X25519 public key.
3. Emissary performs its own Noise-N request decryption.
4. Emissary parses the i2pr-produced 154-byte request plaintext.
5. Emissary reads the receive tunnel ID, next tunnel ID, terminal next router,
   role, request timing, and next message ID from its own parser.
6. Emissary reaches its own transit admission logic.
7. On acceptance, Emissary derives its own tunnel/garlic keys and rewrites the
   reply records.
8. As OBEP, Emissary returns a `TunnelGateway` carrying the garlic-wrapped
   outbound tunnel-build reply toward the exact reply router/tunnel declared
   by i2pr.

A participant-only parser test would be weaker. A full multi-hop live topology
would add no useful information for this Q0 gate and would recreate the old
environment problem.

Inbound Q0 is not required here. i2pr's inbound short-build path already has
strict local trajectory coverage from Plans 112-114, while an independently
routed inbound STBM would pull garlic-delivery work into this pass. That belongs
later in the real data-plane/integration sequence.

## 6. Exact test construction

The executor should implement a test with semantics equivalent to the following
pseudocode. Import spelling may change to match the pinned APIs; the assertions
must not be weakened.

```rust
#[tokio::test]
async fn i2pr_production_stbm_is_consumed_by_emissary_obep() {
    // Emissary owns the reference identity and private key.
    let mut reference = TestTransitTunnelManager::new(true);

    let router_hash_bytes: [u8; 32] = reference
        .router_hash()
        .as_ref()
        .try_into()
        .expect("32-byte router hash");
    let static_key_bytes: [u8; 32] = reference
        .public_key()
        .as_ref()
        .try_into()
        .expect("32-byte X25519 public key");

    let reference_hash = i2pr_proto::Hash::from_bytes(router_hash_bytes);

    // Fixed non-secret creator/reply routing values are adequate.
    let reply_router_bytes = [0x42_u8; 32];
    let reply_router = i2pr_proto::Hash::from_bytes(reply_router_bytes);
    let receive_tunnel = i2pr_tunnel::TunnelId::new(0x1111_1111).unwrap();
    let reply_tunnel = i2pr_tunnel::TunnelId::new(0x2222_2222).unwrap();
    let creator_slot = i2pr_tunnel::TunnelId::new(0x3333_3333).unwrap();

    let hop = i2pr_tunnel::HopSpec::new(
        reference_hash,
        static_key_bytes,
        i2pr_tunnel::HopRole::OutboundEndpoint,
        receive_tunnel,
        reply_tunnel,
    );

    let path = i2pr_tunnel::ShortBuildPath {
        attempt_id: i2pr_tunnel::BuildAttemptId::new(1),
        direction: i2pr_tunnel::TunnelDirection::Outbound,
        originator_hash: None,
        outbound_reply_router: Some(reply_router),
        creator_tunnel_id: creator_slot,
        hops: vec![hop],
        request_time: <nonzero current-or-mock Date>,
        next_message_id: <nonzero u32>,
        options: i2pr_tunnel::BuildOptions::default(),
    };

    let deadline_ms = <later than request_time>;
    let mut state = i2pr_tunnel::short::ShortBuildStateMachine::new(
        path,
        deadline_ms,
    );

    let mut rng = MockRuntime::rng();
    let stbm = state.prepare(&mut rng).expect("i2pr prepare");
    let action = state.deliver_action(stbm).expect("i2pr deliver action");

    let (i2np, record) = i2pr_tunnel::ShortBuildI2npBridge::new()
        .wrap_deliver_action(
            &action,
            i2pr_tunnel::BridgeHeader::Standard {
                message_id: <same nonzero message id>,
                expiration_ms: <valid expiration>,
            },
        )
        .expect("i2pr I2NP bridge");

    let encoded = i2np
        .encode_standard_to_vec(i2pr_proto::MAX_I2NP_PAYLOAD_SIZE)
        .expect("complete standard I2NP message");

    // Independent I2NP parsing/serialization.
    let parsed = crate::i2np::Message::parse_standard(&encoded)
        .expect("Emissary parses i2pr standard-header I2NP");
    assert_eq!(parsed.message_type, crate::i2np::MessageType::ShortTunnelBuild);
    assert_eq!(parsed.payload.as_slice(), action_message_bytes(&action));
    assert_eq!(parsed.clone().serialize_standard(), encoded);

    // Independent native short-build processing.
    let (next_router, response, feedback) = reference
        .handle_short_tunnel_build(parsed)
        .expect("Emissary native short-build handler");

    // Acceptance, not parser-only success.
    assert!(feedback.is_some(), "reference must accept the transit tunnel");
    assert_eq!(next_router.as_ref(), reply_router_bytes.as_slice());
    assert_eq!(response.message_type, crate::i2np::MessageType::TunnelGateway);

    // OBEP must route the generated reply through the declared reply tunnel.
    let gateway = crate::i2np::tunnel::gateway::TunnelGateway::parse(&response.payload)
        .expect("Emissary TunnelGateway reply");
    assert_eq!(u32::from(gateway.tunnel_id), reply_tunnel.get());

    let inner = crate::i2np::Message::parse_standard(gateway.payload)
        .expect("Emissary OBEP inner message");
    assert_eq!(inner.message_type, crate::i2np::MessageType::Garlic);

    // Evidence is digest/stage only; do not print the raw records or keys.
    assert!(record.record_count >= 1);
}
```

## 14. Acceptance criteria

This corrective/completion pass is complete when all of the following are true:

1. Upstream Emissary is pinned exactly to
   `9b43484a21d5a1291c4881cdae62a36c527f8c0f`.
2. The reference instrumentation is test-only and does not alter Emissary
   production code.
3. The Emissary router identity and private key remain Emissary-owned; i2pr is
   given only the router hash and static public key.

   `ShortBuildStateMachine::prepare -> deliver_action` path.
5. The complete I2NP type-25 message originates from
   `ShortBuildI2npBridge`; no hand-built I2NP header or STBM body substitutes
   for it.
6. Emissary parses the standard I2NP message with its own parser.
7. Emissary receives the exact same count-prefixed STBM body emitted by i2pr.

   `TransitTunnelManager::handle_short_tunnel_build()`.
9. A pass requires native policy acceptance (`feedback.is_some()` or an

10. The OBEP output targets the reply router/tunnel declared by i2pr and
    produces the native TunnelGateway/Garlic reply envelope.
11. No daemon, socket, network namespace, VM, container, public I2P network, or
    NTCP2/SSU2 session is used.
12. No new Python code or permanent interoperability harness is added.
13. The test/patch obeys the strict attempt budget.
14. Evidence contains only hashes/stages/non-secret metadata.
