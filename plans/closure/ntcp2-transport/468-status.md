## Outcome

The exact pinned, unmodified i2pd 2.61.0 build at
`635b013a612ff47278ef02acf8580a28e10e26c5` admitted the actual signed i2pr
controlled-loopback floodfill RouterInfo into a frozen five-record private
NetDB. All four independently signed stock floodfill records were generated by
normal stock owners and were dual-transport eligible. Each of four independent
stock owners loaded exactly `5 routers loaded (5 floodfils)`, with all five
owners running in the isolated loopback fixture and no public reseed.

The first fixture execution exposed a real product-side publication defect:
the generic hash encoder's deliberate 512-byte input bound was used for a
full RouterInfo, so I2PControl publication rejected the signed record. The
RouterInfo-specific bounded encoder now accepts the protocol's larger common
structure bound; the hash encoder retains its narrow bound. The corrected
same-plan live execution passed static signature/identity/address preflight,
stock startup admission, and the normal source-owned publisher selection.

The publisher precompute initially disagreed with stock's live target because
it did not model `RouterContext::HandlePublishTimer` excluding a floodfill's
own identity. The selector model now excludes the owner. In the final live
execution, two owners selected the i2pr candidate and two selected another
valid stock floodfill; precomputed and observed candidate counts both equaled
2. There were four normal publication receipts, zero no-tunnel outcomes, and
two stock `Publishing confirmed` receipts. A different valid target is an
admission success and is not treated as a protocol failure.

The same run provided Plan 469's first positive chain: three fresh authenticated
i2pr inbound NTCP2 links, fourteen forwarded I2NP messages, two accepted
third-party RouterInfo stores with response owed, and two product responses
submitted. Two stock publications were confirmed. Plan 469 later completed its
stricter source-to-product correlation and negative/lifecycle matrix; see
[`469-status.md`](469-status.md). This record closes only Plan 468.
