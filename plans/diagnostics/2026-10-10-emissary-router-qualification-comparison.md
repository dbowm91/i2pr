## Actual blockers, not hypotheses

- Plan 431 stopped before implementing persistent/non-loopback SSU2 because AGENTS.md ordinary acceptance excludes root, namespaces, containers, VMs and public-network testing; it had no independently addressed test pair. Existing Plan 161 proves bidirectional stock i2pd loopback SSU2, so the blanket hypothesis that loopback necessarily fails is falsified.
- Plan 099's historical NTCP2 lane never established cross-side authenticated I2NP. Current Plans 410 and 414–424 improved the stock reference observer and current-pin runner; Plan 420 shows one post-validation RouterInfo acceptance marker, then termination not tied to same session and zero I2NP. Plan 424 shows reverse `responder_session_confirmed_read_closed` vs independent helper `session-not-established`; cause is not correlated. No safe wire-crypto change follows.
- Java floodfill Plan 306 accepted and listed i2pr `fR` but never selected it because bandwidth class `Unknown`, so tunnel-dependent SAM holder never started. This is a candidate-selection deadlock; i2pd already passed the complete one-family controlled floodfill matrix (303).
- Plan 432 signed HTTPS SU3 local fixture and restart passed. It does not prove public-network admission.

## Test hierarchy and anti-vacuity requirements

1. **Deterministic protocol unit/state-machine**: same-process fake clock/IO; assert exact canonical vectors, denial, bounded replay/cleanup. No external proof.
2. **Real loopback transport**: different **router identities, keys, datadirs and ports**, same network ID, stock i2pd or stock Java without modification, explicit test-local-address allowance where available. Assert both sides of handshake and real decoded I2NP, not process-wide log presence. This is valid one-family experimental progression, not external reachability.
3. **Controlled multirouter product**: separate normal router processes and functional reference exploratory peers/floodfills (no bootstrap deadlock), signed RouterInfos, real I2NP/NetDB/tunnels/application traffic and stock routing decisions. Loopback may qualify a controlled protocol result but must not count as public advertised reachability. Never silently fall back to zero-hop.
4. **Independently addressed/private LAN qualification**: already-authorized hosts with non-loopback IPs, fresh identities, host-port uniqueness, real UDP/TCP bind/address match; use one stock router family first and second as applicable. Remote labs require owner authorization and a separate explicitly declared acceptance mode. No routine CI root/netns/container/VM/public-I2P.
5. **Normal/public readiness**: two independent router implementation families where specs/CONFORMANCE.md mandates it, operator opt-in, durable keys, honest reachable addresses/RouterInfo caps, acceptance/withdrawal/failure, no anonymity/release claim without audit.

**Oracle counterfactuals:** a positive control should succeed for a known-working stock-to-stock path with equivalent topology; a deliberately bad network ID, wrong identity, port collision, unsupported address, or expired RI should fail predictably. If both stock-to-stock and stock-to-i2pr fail the same pre-wire selection step, classify topology/fixture blocker before touching i2pr wire. If stock-to-stock works but i2pr fails, compare the first exact boundary. A single processed RouterInfo marker is not a fully authenticated session; a timeout or silent close is not a diagnosed crypto failure.

## Standards and evidence vocabulary

- Official NTCP2: https://www.i2p.net/en/docs/specs/ntcp2/ — handshake/RI constraints, network ID mismatch rejection, message-3 m3p2len exactness, silent close after validation errors and persistent static key/IV.
- Network Database: https://www.i2p.net/en/docs/overview/network-database/ — floodfill automatically uses configured shared bandwidth and health; 128 KBytes/s current minimum share, but advertised capability class must match the exact current normative category mapping.
- RouterInfo capabilities: https://www.i2p.net/en/docs/overview/network-database/ — K/L/M/N/O/P/X classes by shared configured capacity; do **not** confuse Kb/s with KB/s or infer a high class from idle utilization.
- Existing i2pr evidence: `plans/closure/ssu2/161-status.md`, `plans/closure/ntcp2-transport/{099,420,422,423,424}-status.md`, `plans/closure/floodfill/{303,306}-status.md`, `plans/closure/core-router-recovery/{430,431,432}-status.md`.

## Unresolved/explicitly out of scope

Whether i2pr's particular NTCP2 silent close is because of a sender mistake, reference helper identity mismatch, session timing, advertisement, or crypto remains **unresolved**. Emissary's `allow_local` tests do not establish public interoperability, and no Emissary external-router interop lane was executed here. Its optional caps override is not acceptable evidence of truthful capabilities. This document does not authorize new root/container/VM/network tests or remove historical conformance evidence.
