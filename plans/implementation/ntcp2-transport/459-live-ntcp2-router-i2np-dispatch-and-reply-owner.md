## Actual source gap

`crates/i2pr-daemon/src/lib.rs::register_ntcp2_service` uses **both** incoming and outgoing `AuthenticatedLink` receive loops to call `router_i2np::dispatch_router_i2np_parts(peer,link_id,&bytes,now_ms)`, then explicitly discards the result (`let _ = ...`). `router_i2np.rs::dispatch_router_i2np_parts` decodes/validates and returns only a typed `RouterI2npOutcome`; it does **not** apply NetDB records, install tunnel-build state, invoke a live service consumer or issue an authenticated response. The real `ServiceProduct::poll_inbound` currently receives SSU2-specific `Ssu2InboundI2np`. Therefore a decrypted NTCP2 frame is not necessarily consumed by the same live router product that SSU2 uses. This is a concrete implementation ownership defect, not an observed stock crypto failure.

**Deliverable:** the ordinary real `i2pr run` NTCP2 initiator **and** responder must deliver authenticated I2NP into the *one existing* daemon NetDB/tunnel/router-control owner, and route meaningful replies over a verified eligible authenticated link.

Classification: **capability** = observable NetDB/router-tunnel effects from authenticated NTCP2; **infrastructure** = typed transport-neutral I2NP ingress and bounded response delivery; **invariant** = no duplicated RouterIdentity, NetDB, service product, decoder, trust attribution, or public listener; **polish** = redacted stage counters.

3. 4. Make real replies from the owner use the existing authenticated `send_blocks`/I2NP send path with Plan-454 wire-budget charging and bounded queue/backoff. Never send to an address supplied only by an untrusted inbound message.
5. Deterministic tests: accepted inbound/outbound DatabaseStore actually changes the product-owned NetDB (or is semantically rejected with a distinct reason); an appropriate DatabaseLookup gets a correctly correlated reply; a short-build/TunnelGateway/DeliveryStatus reaches the expected live consumer; malformed/expired/unknown type is refused.
