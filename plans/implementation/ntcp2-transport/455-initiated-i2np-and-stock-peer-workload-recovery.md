## Root cause and direction

Pinned stock i2pd 2.61.0 (`PurpleI2P/i2pd@635b013a612ff47278ef02acf8580a28e10e26c5`) `libi2pd/Transports.cpp::SendMessage -> SendMessages -> PostMessages -> ConnectToPeer` connects **only after** an I2NP send for a peer without an existing session. `ConnectToPeer` requires a stored valid reachable RouterInfo, `GetPublishedNTCP2V4Address`, permitted loopback/reserved-address policy, compatible NTCP2 version, and a live NTCP2 server. Starting two idle stock daemons and importing each other's RouterInfo does not cause a dial. Plan 452 observed **zero** SessionRequest, auth or decoded I2NP in its 20-second window. This is not evidence of bad i2pr NTCP2 cryptography.

Classification: **capability** = real bidirectional authenticated NTCP2 router I2NP with the pristine reference; **infrastructure** = one bounded ordinary stock router fixture and direct i2pr-initiator adapter; **invariant** = no default-on transport/public egress/observer-only evidence, no secret logging; **polish** = brief reproducible driver and stage receipt.

## Production and fixture work — one bounded coherent pass

1. **Preserve the known-good isolation.** Reuse Plan 452's disjoint 0700 temporary i2pd roots and explicit `--datadir` plus `--conf`; assert per-child `router.info` belongs to the correct root before traffic. No ambient `~/.i2pd`, symlinks, root namespaces, Docker, external network, patching stock i2pd, or opportunistic reseed. Pin source/binary/version and separate identity/hash/network ID, port and key/IV. Ensure stock `ntcp2.enabled=true`, `ntcp2.published=true`, fixed loopback v4 address/port, `nat=false`, appropriately scoped `reservedrange=false`, classical `v=2` and matching true signed RouterInfo, avoiding unsupported PQ/dialect claims.
2. **Priority Gate A: immediately test actual i2pr-initiated NTCP2**, without making an *unrelated stock-to-stock dial trigger* a prerequisite. Start one pristine normal stock-i2pd responder and use the existing controlled i2pr NTCP2 dialer/initiator in `crates/i2pr-runtime/src/ntcp2_runtime.rs` and `ntcp2_link.rs`. Authenticate a full same-session SessionRequest → SessionCreated → SessionConfirmed; deliver a real small I2NP DatabaseStore or DeliveryStatus through `AuthenticatedLink::send_blocks`, observe stock process receive and/or protocol-level correlated reply, plus fragmented/max-frame and reverse data where supported. TCP connect/Noise-complete alone is **not** successful I2NP. For a failure, classify exact source-owned stage and make **one implementation correction** with deterministic regression before retry; do not register another per-log observer plan. Preserve and consume bounded received-frame leases and exact wire byte accounting.
3. **Priority Gate B: make the stock-reference positive control actually send.** Inventory current pinned i2pd `Transports.cpp::PostMessages` reachability path, `NetDb.cpp`, `ClientContext.cpp`, `SAM.cpp` and RouterInfo classification. Provide an actual **stock-owned** outbound operation (e.g., external SAM v3.1 STREAM destination/session and a bounded tunnel/NetDB operation) on the seeded peer topology; maintain a sufficient set of independently signed stock reference identities/known-good floodfills and transit participants if required, not only two unselectable peers. Confirm the selected peer is the intended role, the i2pd-generated I2NP enters `Transports::SendMessage` and reaches a real TCP dial. Do not assume the standard SAM session HELLO or simply starting a daemon generates I2NP. Avoid synthetic code injection into reference implementation. Keep the stock-to-stock control when diagnosing *stock peer-selection* but do **not** discard a successful Gate A when that control is ineligible.
4. **Gate C: stock→i2pr link.** Once a genuine stock dial trigger and reference self-control exist, replace recipient with an i2pr responder using the same signed NTCP2 address/peer-selection topology. Require fresh SessionConfirmed validation, bidirectional encrypted I2NP data with a correlated message ID, replay and duplicate-link rejection. Compare the first difference to pristine stock/stock and **only then** change i2pr transport/protocol source. No cryptography rewrite based on wrapper timeouts.
5. **Bounded negative matrix:** no dial trigger; missing/unreachable or unpublished NTCP2 address; reserved local address disallowed; old/other-version RouterInfo; wrong network ID, static key/IV, signature, or port; early EOF and half-written SessionConfirmed; malformed frame/block, padded/large frame, cancellation during admission/send, peer restart. Distinguish `no-send-attempt`, `peer-ineligible`, `tcp-not-dialed`, `tcp-connect-failed`, `noise-rejected`, `session-authenticated-no-i2np`, `i2np-direction-failed`; emit only bounded redacted stage counts and per-run opaque correlations.
6. **Budget/escape rule:** finite timeouts (long enough for real stock bootstrap and tunnel startup, not a fixed idle-only 20 seconds), at most one first-run per frozen topology/direction plus a repeat after **an exact rooted configuration/source fix**. Missing stock tunnel prerequisites are a **fixture prerequisite** outcome; retain Gate A independent progress and do not recurse into an indefinite new micro-plan.
