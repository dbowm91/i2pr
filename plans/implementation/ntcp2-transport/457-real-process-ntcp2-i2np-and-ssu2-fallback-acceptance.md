## Required result

Use a separately launched compiled `i2pr run` with a single persisted RouterIdentity and independent transport keys, two strictly local independently provisioned reference i2pd 2.61.0 peers as necessary, and **one** daemon RouterInfo/NetDB/router-to-router I2NP dispatcher. Prove normal-process authenticated NTCP2 in both initiator/responder roles, real decoded I2NP with a correlated request and reply, and NTCP2/SSU2 one-family transport coexistence/failover without re-creating the router. Distinguish controlled loopback from later independently addressed and two-family normal/public qualification.

**Capability:** controlled whole-daemon router I2NP over TCP and UDP. **Infrastructure:** bounded choice/retry/admission/health snapshots and external launcher. **Invariant:** default NTCP2 disabled, no public address claim, no identity sharing with SAM destinations, no duplicate NetDB/tunnel owner. **Polish:** exact operator config plus failure classifications.

## Work and acceptance

1. Start real daemon with Plan 456 guarded NTCP2 profile (normal factory, not separate helper), controlled SSU2 profile, same network-ID and signed per-transport RouterAddresses. Start ordinary exact-pinned i2pd in disjoint `--datadir` roots; no reference patches, WAN reseed or host-side ambient profile. Provide signed RI out-of-band in controlled fixture, check transport selection and both listeners actually bound.
2. Exercise **i2pr initiator** using the same validated peer directory/send path that the ordinary daemon uses and verify same-session authentication and actual bidirectional I2NP. Exercise **i2pd initiator** only after Plan 455's stock-owned send trigger is demonstrably real; assert selected peer + incoming decoded I2NP to the daemon dispatcher. Do not treat a TCP SYN, Noise established or generic process-level counter as a full pass. Correlate each direction with decoded frame plus recipient-owned I2NP response and no misidentified peer.
3. Reuse existing Plan 161 one-family SSU2 interoperability as a *known-good reference*, but show the normal process's actual outbound choice: NTCP2 to a peer advertising only NTCP2, SSU2 to a peer advertising only SSU2, and one peer offering both. Terminate only NTCP2 and verify eligible SSU2 delivery continues; then terminate only SSU2 and verify NTCP2 continues, subject to real signed RI/selection. Use bounded retries/priority/backoff, deterministic no-dial-disabled controls, separate transport failures. No artificial traffic suppression to manufacture fallback.

Negative tests: identity/network/RI address mismatch, wrong key/IV, stale and rejected peer, full half-open queues, stalled handshake, peer reboot, malformed/oversize frame, cancellation before and after authentication, governor contention, output/inbound queue drain and no orphan tasks; privacy-safe aggregates only.
