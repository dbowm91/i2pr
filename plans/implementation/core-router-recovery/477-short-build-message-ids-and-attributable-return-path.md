## Source facts and explicit uncertainties

One Plan 474 exact-pinned normal run sent two build requests and installed one, while the other timed out at inbound-build. Twenty-four authenticated ShortTunnelBuild candidates included five from the selected terminal peer, but none with the expected message ID (all five were different IDs). Stock aggregate transit observations cannot establish any of the failed attempt's hops or terminal return. This is **not** evidence to accept unmatched replies or modify strict authenticated-peer/ID checks.

Source inspection shows two independent implementation divergences:
1. crates/i2pr-tunnel/src/multirecord.rs::prepare_short_build_message passes one next_message_id into **every** hop plaintext; pinned unmodified i2pd 2.61.0 Tunnel.cpp chooses independent IDs for intermediate hops, reserving the designated final response ID for the last real hop. TransitTunnel.cpp forwards a nonterminal ShortTunnelBuild with the decrypted SEND_MSG_ID field, and an endpoint takes its separate ShortTunnelBuildReply/garlic return branch. The reuse is at least a metadata/fingerprinting concern; it has **not** been proven to cause the timeout.
2. crates/i2pr-daemon/src/service_product.rs initializes Plan212TunnelIdAllocator from the fixed 0x51A7_9300 seed and derives build message IDs using a fixed XOR and direction bits. The production source thereby yields predictable initial IDs across process restarts. It must use OS-backed cryptographic randomness, with collision handling in live/pending/retained tunnel and message-ID scopes. Stable test IDs are permitted only behind explicitly test-owned injection.

In crates/i2pr-daemon/src/exploratory_build.rs::submit_path, RouterDeliveryOutcome::Accepted records queue admission, not proof of socket write. Strict reply matching currently binds terminal authenticated peer plus message ID for inbound ShortTunnelBuild, and for outbound TunnelGateway uses authenticated terminal peer, tunnel ID, garlic authentication, then inner reply ID. Preserve those protections. Do not infer a build failure from unrelated stock exploratory traffic.
