# Plan 458 — Secondary recovery: attach normal SAM sessions to the shared network product

Status: **registered / ready, execution priority P2 (after NTCP2 Plans 455/456)**. Date 2026-10-10. Owner core-router-recovery. Corrective successor to Plan 451's immutable `plans/closure/core-router-recovery/451-status.md` (`blocked-normal-sam-remote-product-fabric-not-composed`). This is a separate missing **product composition** seam; it must neither block nor modify NTCP2 transport-layer work. Hard dependencies: Plan 450 Gate A, existing `ServiceProduct::start_over_existing_daemon` source contract and validated Plan 432 cache. No NTCP2, two-host LAN, floodfill or Java prerequisite.

## Objective and boundaries

`crates/i2pr-daemon/src/lib.rs::register_sam_service` constructs an isolated `SamServiceState::new`; `crates/i2pr-daemon/src/sam.rs::execute_session_create` builds a `SamLocalProductFabric`. Separately, `register_ssu2_service` starts the network-backed `ServiceProduct::start_over_existing_daemon` only for active service groups. The normal SAM session has no narrow handle for the bounded SSU2/NetDB/destination group producer. Bridge the **real daemon-owned shared product** to SAM STREAM sessions while preserving the tested local-only compatibility profile as a distinct deliberate mode.

Classification: **capability** = SAM-created destinations exchanging real remote I2P data (only when tested); **infrastructure** = narrow remote-product session factory/dispatch handles; **invariant** = single router identity/socket/NetDB owner, private per-destination identity, local loopback SAM and default off; **polish** = actionable route readiness/negative diagnostics.

## Packages

1. Audit `lib.rs::register_sam_service`, `register_ssu2_service`, `sam.rs::execute_session_create`, `service_product.rs`, `destination_streaming.rs`, `destination_tunnels.rs`, `service_lifecycle.rs` for shared topology, required Bootstrap cache and current service group gate. Design narrow `NetworkDestinationProductFactory` (or equivalent existing typed API) instantiated by the one SSU2 router owner, accessible to SAM through a bounded Arc handle or supervised channel. Avoid a global service locator, duplicate SSU2 socket, eager always-on Destination groups, and circular service readiness deadlock. SAM must not report network-usable if product is unavailable.
2. Each SAM session CREATE is transactional: private DestinationIdentity + validated LS2/ECIES material, remote-product tunnel/Streaming registration, per-session rollback on error, owned finite resource quotas and cancellation; close removes only the session's material. Existing `SamLocalProductFabric` must remain explicit for local-only tests, never silently selected for a requested remote route. Preserve versioned SAM replies and session identity invariants.
3. Drive real black-box `i2pr run` with external SAM client and pinned i2pd reference: Gate B authenticated SSU2/NetDB and Gate C **nonzero-hop** destination Streaming request/reply with exact bytes. No localhost-same-router or zero-hop shortcut. Preserve external M6 `run-streaming.sh` failure at stock SAM SESSION CREATE as a separately diagnosed reference fixture if it recurs. Do not turn it into new i2pr protocol rewrite without a source-owned boundary.
4. Fault matrix: bootstrap unavailable, stale peer RI, rejected LS2, no tunnel peers, saturated queues, session reuse/delete, parent cancellation, router restart, abandoned client, unequal destination/router keys and no leaked session. Aggregate redacted readiness distinguishes `SAM-serving` from `remote-product-ready` and `application-complete`. Existing default-off SAM/I2CP/console/transport posture remains.
