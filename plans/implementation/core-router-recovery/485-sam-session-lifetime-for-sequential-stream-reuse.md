# Plan 485 — SAM session lifetime for sequential stream reuse

**Status:** registered / **ready, P0 application-functionality owner** (2026-10-16). **Owner:** daemon SAM `finish_raw_stream` standalone cleanup, `sam_stream_final_acceptance` lifecycle baselines. **Baseline:** `work/plans-477-480-router-recovery@cc9d8f5d`. **Authoritative predecessor:** `plans/closure/core-router-recovery/478-status.md` (7r7te3fb/tnm6su4j two-row teardown readings; union-gauge correction). No new ADR: the renegotiated contract lives at implementation-plan level (Plans 147/149 lineage + `sam_stream_final_acceptance` baselines), not architecture level; this plan and its closure carry it. This plan does not depend on Java Plans 475/479, LAN Plan 476, or PR review Plan 473.

## Concrete source-boundary discrepancy

Exact-pin lanes `7r7te3fb` and `tnm6su4j` show the same two-row `session_teardown` reading: forward STREAM echo completes, then `finish_raw_stream`'s standalone last-stream cleanup tears down the LIVE session (`cause_code=3, session_live=1`, service driver present post-union), so the reverse-leg `STREAM ACCEPT` fails fast at session lookup (`InvalidId`, never parks — hence no ACCEPT-SYN wait rows) while stock hangs ~99 s. Verified mechanics: per-command (CONNECT/ACCEPT) sockets stay `UtilityReady` so their close never tears down; session deaths are exactly control-socket close (cause 2), last-attachment finish on primary non-forwarding sessions (cause 3), and create rollback (cause 1); `SESSION REMOVE` covers only 3.3 children, so standalone sessions have no explicit destroy. Self-composed suites pass because their streams are CONCURRENT (attachment count never hits 0 mid-test). What dies is SEQUENTIAL reuse with a zero-attachment gap — SAM-normal multi-stream use and exactly the lane's leg shape. No counts-only attribution narrows further (waiter-gating cannot save sequential legs: no waiter is parked at finish).

**Capability:** one SAM session survives sequential streams — a completed CONNECT followed (after a zero-attachment gap) by a second CONNECT or a parked ACCEPT on the same session ID succeeds instead of `InvalidId`. **Infrastructure:** explicit control-close session lifecycle + reworked baselines. **Invariant:** loopback-only, exact-pinned unmodified stock references, sanitized counts-only receipts, fail-closed session/bridge/driver/counter teardown, no support/capability/advertisement change, `max_sessions` capacity bound unchanged.

## Ordered work packages

1. **Remove the standalone last-stream teardown.** In `finish_raw_stream` (`crates/i2pr-daemon/src/sam/raw_stream.rs`, the `attachment_count_for == 0` gate), stop calling `teardown_session(RawStreamFinished)`: sessions die only on control-socket close, `SESSION REMOVE` (children), or create rollback. Keep the attachment release, connection removal, and close receipt exactly as-is; keep the `SessionTeardownCause::RawStreamFinished` variant and its INFO shape for any residual caller (none expected — compiler-verified), so lane parsers keep parsing.
2. **Rework the lifecycle baselines to explicit control-close semantics.** `crates/i2pr-daemon/tests/sam_stream_final_acceptance.rs` (618/999/1135/1364/1447/1528-9) and `sam_plan146_reference.rs:663` assert `session_count() == 0` after stream drops; audit each site's socket ownership and retain an explicit session control socket per session, closing it to reach baseline (cause-2 path) instead of relying on cause-3. No weakening: baselines must still reach zero sessions/attachments, now via an owned close.
3. **Bound idle retention.** With cause-3 gone, idle standalone sessions hold bridge/driver/pool/counter residency until control close. Show: `max_sessions` still caps session count; the default 60 s `command_timeout` (`DEFAULT_SAM_COMMAND_TIMEOUT_MS`) already caps control-socket idleness; no new unbounded retention (drivers/pools are per-session bounded structures already governed by existing limits). Record the analysis in the closure, not as a new limiter.
4. **Regression tests (deterministic, no stock):** sequential reuse on one session — CONNECT, clean finish, attachment count 0 with session live (`session_registry.contains`), second CONNECT (or parked ACCEPT waiter → Established) on the same session succeeds; control-socket close still tears down (cause 2, session gone); create-rollback still reports not-live. Inversion-probe each new assertion and revert.
5. **One externally meaningful lane after the source fix:** exact-pin `run_plan458_sam_product.py`; required reading order — forward echo completes with NO cause-3-live teardown row, reverse ACCEPT parks (ACCEPT-SYN wait rows appear on expiry, or Established), then the DATA decision table. A second lane is licensed only by a new material change, never by rerun appetite.
6. Negative controls: concurrent streams still share/exit cleanly; duplicate SESSION CREATE still fails closed; control-socket drop mid-stream still tears down; child-session (3.3) semantics unchanged; shutdown baselines unchanged.
