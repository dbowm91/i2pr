## Concrete source-boundary discrepancy

One exact-pinned stock-i2pd four-peer replay produced **4/4** selected, admitted, emitted, authenticated-reply-matched and installed short-build attempts. The normal destination bridge held **two valid real inbound receive IDs** and a signed Standard LS2 with **two genuine leases**. Nonetheless `sam.rs::execute_router_network_session_create` received `service_router_network_summary` with **0/2 matching inbound owner registrations** and correctly rejected `destination-summary-incomplete`.

Code analysis gives a bounded causal search, not a proved root cause:
- `crates/i2pr-daemon/src/service_product.rs::provision_all_service_router_material` calls `manager.install_service_router_material`, then `register_inbound_tunnel_owner` for every receive ID, and checks owner presence **before returning**. The later deferred-activation path calls this helper and responds to SAM.
- Separately `ServiceProduct::poll_inbound` / post-activation paths register owner before appending receive to the bridge. `poll_inbound` expiry/eviction and failed bridge-append paths **unregister** owners. The SAM-session retirement path also unregisters per-session receive IDs.
- `crates/i2pr-daemon/src/service_tunnels.rs::service_router_network_summary` reads the bridge's receive IDs then queries **that manager's** `inbound_tunnel_owners` map. `unregister_router_network_sam_destination` also removes all receive IDs. These paths may race lifecycle/expiry, encounter an unexpected manager instance, or observe mixed generations. **No particular hypothesis is established**; test rather than guessing.
- The historical Plan 471 other attempts stopped before postbuild at an unmatched inbound or outbound stock reply. That is a separate transit/return-path problem; do not conflate it with this reproducible post-install predicate.

**Capability:** normal `i2pr run` creates a network-backed SAM Destination with genuine inbound/outbound *nonzero-hop* tunnels, durable correctly registered inbound ownership, signed LS2, and bidirectional STREAM payload to independently routed peers. **Infrastructure:** transactional per-destination owner/lease snapshot contract and lifecycle regression. **Invariant:** one daemon-owned tunnel manager and router socket, fail-closed inbound dispatch, no forged owner, zero-hop or fake LS2, no RouterIdentity/DestinationIdentity linkability leak. **Polish:** bounded owner-transition cause without sensitive IDs.
