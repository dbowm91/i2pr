# Plan 481 — Source-owned router delivery completion for nested multihop build attempts

**Status:** registered / ready, P0 independent interface owner (2026-10-13). **Owner:** daemon router-delivery capability and transport runtime outbound socket writers; its consumer remains the already active Plan 477 build coordinator. **Baseline:** `work/plans-477-480-router-recovery@9ac340af198da614d7f03d0d69ecfdd0a0d66aa7` (draft PR #46). **Predecessor authority:** `plans/closure/core-router-recovery/477-status.md` (`in-progress-per-hop-collision-scopes-landed-first-divergence-unattributed`) and `480-status.md` (`in-progress-bounded-runtime-observer-landed-process-consumer-open`). **Scope justification:** a durable cross-owner completion seam is missing between the transport writers and a tunnel-build attempt. Plan 477 owns validation of one build/reply, not a new general transport event contract; Plan 480 owns private SSU2 host evidence, not nested build tracking. This is a distinct shared source interface, not another observer-only plan for an unchanged timeout.

## Evidence and precise problem

- `crates/i2pr-daemon/src/router_i2np.rs::RouterDeliveryService::deliver` returns `RouterDeliveryOutcome::Accepted` immediately after `Ssu2RuntimeService::send_i2np` queue admission. `deliver_with_transport` prefers SSU2 and falls back to an established NTCP2 route on `NoActiveSession`. Neither accepted result proves a socket write; `RouterDeliveryTransport::Ssu2` lacks the exact link generation in its caller-visible outcome.
- `crates/i2pr-daemon/src/exploratory_build.rs::submit_path` registers a pending build after delivery admission. For an outbound-backed inbound build, `compose_outbound_build_deliveries` uses `OutboundGatewayRole::forward_cells`, creates **up to eight** TunnelData cells, gives each its own fresh transport I2NP header ID, and delivers those cells to the *outbound tunnel first hop*, while the nested ShortTunnelBuild is addressed for the *inbound gateway*. `TunnelPayloadHeader.message_id`, outer ShortTunnelBuild header ID, per-hop SEND_MSG_ID, final reply ID and TunnelData transport IDs are distinct logical namespaces, even when an implementation currently reuses one numerical value.
- `crates/i2pr-runtime/src/ssu2_qualification_observer.rs` already emits authenticated session and actual UDP write events with ephemeral message IDs and link generation in a private bounded 512-event observer. This is useful **source input**, but does not associate emitted cells with the originating build, nor cover the NTCP2 writer. It is not permission to serialize message IDs or expose them to stock peers.
- Latest `run_plan458_sam_product.py` run installed its direct outbound bootstrap and timed out on the outbound-backed inbound build. Authenticated message candidates from the expected terminal peer did not match the expected reply ID. The actual originator egress and exact remote forwarding path are not yet proven. Aggregate i2pd events cannot be substituted for request-attributed evidence.

## Classification and boundaries

**Capability:** a pending normal-router tunnel-build attempt can be classified as *not emitted*, *all required originator cells emitted*, *partial emission*, *transport generation changed*, or *emitted but no attributable response* before interpreting a build timeout; Plan 477 owns final response classification. **Infrastructure:** one typed bounded, private, cancel-safe `RouterDeliveryTicket` / completion contract spanning shared SSU2 and NTCP2 writes, with a per-build fanout aggregation boundary. **Invariant:** completion means OS socket/write-owner acceptance only, never remote receipt or stock acceptance. Provenance must derive from the actual selected authenticated peer, transport family, exact link generation and socket writer, not caller-provided logs or raw message-ID equality. No public control API, peer observable token, persisted raw identity, service-to-router fingerprint, or new transport scheduler. **Polish:** finite stage taxonomy and clear category-only test receipts.

## Bounded implementation packages

1. **Freeze source ownership.** Map `RouterDeliveryService`, `Ntcp2RouterDeliveryRegistry::deliver_with_link`, the NTCP2 writer, SSU2 send/fragment/staging/`UdpSocket::send_to`, `Ssu2QualificationObserver`, `ExploratoryBuildCoordinator::submit_path`, and `compose_outbound_build_deliveries`. Name concrete handoff and race semantics on cancellation, retransmission, expired build, socket disappearance, link generation switch and queue backpressure. Establish whether `Accepted` has no transport family or link-generation on any branch; do not assume all queues behave identically.
2. **Define a narrow typed completion capability.** At admission produce an unforgeable *process-local* ticket scoped to one delivery request, actual peer, family, link generation, deadline and owning router-delivery service. It is not an I2NP field. Emit from the **socket writer**, not the caller or pre-send queue. On SSU2 fragmentation, specify whether success means every contributing datagram was successfully submitted to the UDP socket; a partial fragment submission is an explicit partial state. On NTCP2, report the chosen transport writer's write/flush threshold consistently, document what remains unobservable about the remote peer. A request rejected before enqueue has a terminal rejected state. Tickets cannot be reused across generations.
3. **Bind nested fanout without conflating identifiers.** Define a local-only `BuildDeliverySet` for one `BuildAttemptId`, collecting the per-cell tickets from the route generated by `compose_outbound_build_deliveries`. Keep distinct `inner_build_outer_id`, `terminal_reply_id`, `tunnel_payload_id`, each `TunnelData transport_id`, and each individual writer receipt. Do not equate the TunnelData source's I2NP header ID with the terminal build reply ID. If any cell fails, classify partial emission, cancel remaining tickets, and release/retire pending IDs according to Plan 477's existing replay protection. No false atomic send promise: already emitted cells may transit even if siblings fail.
4. **Consumption seam to Plan 477.** Expose a narrow producer-owned completion channel or synchronous inspect handle to `ExploratoryBuildCoordinator` and `await_destination_build_install`; do **not** log the correlation map. The build owner must be able to combine writer disposition with strict, unchanged authenticated terminal-peer/reply-ID checks. A write receipt can eliminate "never sent" as a local cause but cannot prove the i2pd terminal's receipt. For end-to-end paths with an outbound tunnel, distinguish first-hop transport submission from tunnel endpoint recovery, intermediate forward, terminal build processing and inbound reply arrival. No stock-stage event may be claimed without stock-owned corroboration.
5. **Deterministic failure-before/pass-after matrix.** Simulate: accepted-then-closed before write, timeout queued, partial 1-of-N TunnelData cell writes, fragmented UDP partial, stable successful authenticated session write, NTCP2 writer fail or replacement, drop/restart/cancel, deadline after admission, two same-peer concurrent builds with distinct link generations, stale completion after tombstone expiration, counter exhaustion/overflow. Tests must reject a pre-write "success," stale generation or forged phase; verify no identifier/endpoint leaks to disk or logs. Ensure all tickets and queue slots drain/release on cancellation or termination; count zero new lingering tasks.
6. **Bounded mixed-router handoff.** After deterministic tests, route **one** amended exact-pinned unmodified i2pd 2.61.0 Plan-458 normal SAM attempt with source-owned egress disposition. Preserve old peer/ID strictness and choose the *earliest* provable failed stage. If all TunnelData cells emitted but matching reply never arrived, write `origin-emitted/remote-stage-unproven` unless a genuine stock-owned stage can be attributed. Do not replay unchanged trials, fabricate receipt tokens, inspect private stock APIs, weaken any identity checks, or require unavailable physical LAN.
